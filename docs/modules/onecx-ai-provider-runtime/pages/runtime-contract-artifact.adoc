= Runtime Contract Artifact

The `onecx-ai-provider-runtime` release publishes a **versioned, immutable runtime contract
artifact** in addition to the primary JAR. The contract is the OpenAPI document for the internal
runtime service (`src/main/openapi/openapi-runtime.yaml`). It is attached to the release with the
classifier `openapi-runtime` and type `yaml`, so it is published to the Maven repository under the
same immutable version as the binary.

== Purpose

Before this artifact existed, the runtime OpenAPI contract only lived in source, so consumers had
no way to depend on an immutable, version-pinned contract. Consumers now depend on a Maven artifact
instead of fetching a branch file.

== Maven coordinates

[cols="2",options="header",]
|===
| Coordinate | Value

| GroupId
| `org.tkit.onecx`

| ArtifactId
| `onecx-ai-provider-runtime`

| Version
| the released version (set by the release process; immutable once published)

| Type
| `yaml`

| Classifier
| `openapi-runtime`
|===

In the repository layout the file sits next to the primary artifact as
`onecx-ai-provider-runtime-<version>-openapi-runtime.yaml`.

Resolving it as a Maven dependency:

[source,xml]
----
<dependency>
    <groupId>org.tkit.onecx</groupId>
    <artifactId>onecx-ai-provider-runtime</artifactId>
    <version>RELEASED_VERSION</version> <!-- a published release version, e.g. 1.2.3 -->
    <classifier>openapi-runtime</classifier>
    <type>yaml</type>
</dependency>
----

Both `<classifier>openapi-runtime</classifier>` and `<type>yaml</type>` are required — without them
the dependency resolves to the primary JAR rather than the contract.

== Immutability and release behavior

* The contract is bound to the release **version**, not to a branch. Once a version is published,
  its `openapi-runtime.yaml` is immutable: the same version always resolves to the same contract.
* The artifact is attached during the Maven `package` phase (via
  `build-helper-maven-plugin:attach-artifact`), so it is included in the release publish together
  with the primary artifact, under the same version.
* The primary JAR is unchanged; the contract is an additional classified artifact published
  alongside it.
* Consumers **must use a released version** for client generation or contract checks — never a
  branch source file. Branch contents are mutable and carry no version guarantee.

== Compatibility promise

The contract pins the internal text-dispatch and provider-health API. Two operations are guaranteed
to remain stable in shape:

* `/internal/runtime/chat` — operation `chat`; request `RuntimeChatRequest` and response
  `RuntimeChatResponse` (message is a `string`).
* `/internal/runtime/provider-health` — operation `getProviderHealthStatus`; request
  `ProviderHealthRequest` and response `ProviderHealthStatus` (status constrained to
  `HEALTHY` / `UNHEALTHY`).

Compatibility is enforced by tests that fail on signature or type drift along the text dispatch
path:

* `RuntimeRestControllerTest` — typed request/response shape for the text-dispatch and
  provider-health endpoints.
* `RuntimeChatServiceReflectionTest` — reflection assertions on method signatures, JAX-RS
  annotations, and DTO field types tied to the dispatch path.
* `OpenApiContractPublicationTest` — validates the published OpenAPI contract file is present and
  complete (openapi, info, paths, text-dispatch operation, provider-health operation, and the typed
  dispatch schemas).
